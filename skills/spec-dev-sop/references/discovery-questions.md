# 需求澄清提问清单

阶段 1 使用。原则：**用选项提问，把默认值写进选项里让用户改**；一次最多 4 问；用户答不上来就给建议并标注「按此假设推进」。

## 最小问题集（每次都问）

1. 谁在什么场景下用？不做会怎样？（判断值不值得做）
2. 验收标准是什么？给我一句能判断真假的句子。（防止「感觉不对」反复返工）
3. 明确不做什么？（唯一的范围防线）
4. 涉及数据与权限吗？新建表/改字段/迁移历史数据？有哪几种角色？
5. 兼容压力：老接口、老数据、老客户端还要不要活？
6. 什么时候要？这决定方案做多大。

## 按需求类型追加

### 新增接口

- 谁调用：前端页面、其他服务、还是外部？
- 幂等要求：重复请求会怎样？要不要幂等键？
- 返回体：分页还是全量？需要哪些字段？空列表返回 `[]` 还是 `null`？
- 失败约定：业务错误用 HTTP 4xx 还是 200 + 业务码？（先对齐现有约定，别自创）
- 限流与配额：有没有调用频率上限？
- 是否要进权限白名单/黑名单？

### 修改既有接口

- 老客户端还在用吗？能不能加字段（安全）还是必须改字段（破坏性）？
- 破坏性变更要不要开版本 `/api/v2/`？
- 前端是否同批上线？有没有灰度或开关？
- 现有测试会不会因此失败？提前跑一遍。

### 前端页面/组件

- 目标设备：桌面、移动、都要？最小宽度？
- 空状态、加载态、错误态、超长文本分别长什么样？（这四态最常被漏）
- 数据从哪来：新接口还是复用？失败时展示什么？
- 是否需要分页/无限滚动/搜索/排序？默认排序是什么？
- 交互细节：提交后是否禁用按钮？是否需要二次确认？
- 有没有设计稿？颜色和间距取设计稿还是取现有组件库？

### 权限相关

- 角色清单是哪些？每个角色能做什么、不能做什么？
- 越权访问他人资源返回 403 还是 404？（404 更安全，但要和团队一致）
- 未登录跳转登录页还是直接 401？
- 权限判断放在哪一层：中间件、视图还是服务层？
- 前端隐藏按钮算不算安全措施？（不算，后端必须再校验）

### 数据模型变更

- 新字段可为空吗？默认值是什么？
- 历史数据怎么填？一次性脚本还是懒加载？
- 要不要加索引？查询条件是什么？
- 是否需要软删除？删除后唯一约束怎么处理？
- 迁移可重复执行吗？失败能回滚吗？

### 缺陷修复

- 复现步骤、期望结果、实际结果。
- 影响范围：只影响某个用户/某种数据，还是普遍？
- 是代码 bug、数据脏了，还是需求理解偏差？（三种修法完全不同）
- 线上有没有临时止血手段？
- 要不要补回归测试防止再犯？（默认要）

### 重构

- 动机是什么：可读性、性能、还是要加新功能才不得不动？
- 行为是否必须完全不变？有对照的测试吗？（没有就先补测试再重构）
- 一次改多大？能否拆成几个可独立验证的小步？
- 老代码有没有外部依赖（被别人 import）？

### 依赖升级

- 为什么要升：安全漏洞、新特性、还是被其他依赖倒逼？
- 跨几个大版本？有没有 breaking change 清单？
- 升级后要跑哪些测试？有没有回归清单？

## 复述确认（必做）

澄清完用 5 行以内复述：

```
我的理解：
1. 要做的是 ……
2. 不做的是 ……
3. 验收标准是 ……
4. 我打算 ……
理解对吗？有偏差请现在纠正。
```

不复述直接开工，后面大概率返工。
